Privacy Policy

OpenClaw Automations · Last updated 21 September 2026

1. Who this applies to

OpenClaw Automations ("the application") is a private automation tool operated by Nejat Ozcimen. It is used by its operator only, on the operator's own Google account. It is not offered to the public and has no other users.

2. What data the application accesses

When the operator grants access, the application may read and write the following data in the operator's own Google account:

  • Google Calendar — calendar events.
  • Google Drive — files and folders created or opened by the application.
  • Google Sheets — spreadsheet contents used by automated workflows.
  • Gmail — message contents, for reading and sending mail on the operator's behalf.

The application does not access data belonging to anyone other than the operator.

3. How the data is used

Data is used solely to carry out the automation tasks the operator has configured — for example creating a calendar event, appending a row to a spreadsheet, or summarising incoming mail. It is not used for advertising, profiling, or training machine-learning models.

4. Storage and retention

The application runs on a private server rented by the operator. OAuth access and refresh tokens are stored encrypted on that server. Workflow execution records may temporarily contain the data a workflow processed; these records are kept on the same server and are pruned as they age. No copy of the operator's Google data is kept anywhere else.

5. Sharing

Data obtained through Google APIs is not sold, rented, or shared with third parties. It is not transferred to any other service except where a workflow the operator explicitly built sends a result to a destination of the operator's own choosing (for example, the operator's own Telegram account).

The application's use of information received from Google APIs adheres to the Google API Services User Data Policy, including the Limited Use requirements.

6. Security

The server is reachable only over HTTPS. The workflow interface is protected by HTTP authentication and by two-factor authentication on the application account. Secrets are stored in files readable only by the server's administrative user.

7. Revoking access

The operator can revoke the application's access at any time at myaccount.google.com/permissions. Revocation invalidates the stored tokens immediately; the tokens are then deleted from the server.

8. Children

The application is not directed at children and is not used by anyone other than its operator.

9. Changes

If this policy changes, the revised version will be published at this address with a new "last updated" date.
